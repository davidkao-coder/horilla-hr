# SA-03 功能規格（Think4U HRMS）

> 每個模組：流程 → 狀態機 → 畫面/URL → 權限 → 程式位置。
> 演算法細節在 SA-04，此處只描述流程與規格。

---

## 1. 前台 Portal（員工自助）

**URL**：`/portal/`｜**程式**：`think4u/portal_views.py`、`portal_urls.py`
**畫面**：手機 App 風格單頁，底部 5 個 tab

| Tab | 功能 | 提交端點 |
|---|---|---|
| 🕐 打卡 | 即時時鐘、上/下班打卡、公司/外勤切換、每日驗證碼；底部摺疊「補打卡申請」| `portal-clock-submit` / `portal-correction-submit` |
| 📅 請假 | 假別下拉（只列有配額者）、起訖日+時間、附件、即時算工作時數與可下班時間；摺疊「申請給假」| `portal-leave-submit` / `portal-leave-grant-submit` |
| ⏱️ 加班 | 日期/起訖/事由；顯示「我送出的」+「主管指派的」| `portal-overtime-submit` |
| 📊 出勤 | 本年度 1–12 月切換；月摘要（正常/遲到/早退/缺勤/總工時）+ 每日明細 + **異常日快捷申請**（📝補打卡 / 📅請假 / ⏱️加班，自動帶入該日期）| — |
| ⚙️ 設定 | 個人資料（頭像/姓名/Email/電話/生日/性別/緊急聯絡）+ 銀行資訊 | `portal-personal-submit` / `portal-bank-submit` |

**右上角**：登出；有後台權限者顯示「進後台」連結。

## 2. 加班指派（主管發起）

**程式**：`think4u/overtime_views.py`｜**Model**：`OvertimeAssignment`

### 狀態機
```
        主管建立
           │
           ▼
   pending_employee ──員工拒絕(需理由)──▶ employee_rejected（終）
     │         │
     │         └──主管取消──▶ cancelled（終）
     │ 員工確認
     ▼
   pending_hr ──HR駁回(需理由)──▶ hr_rejected（終）
     │ HR核准
     ▼
   hr_approved（終）
```
> `cancelled` 僅在 `pending_employee` 階段可執行。

### 畫面與權限
| 畫面 | URL name | 權限 |
|---|---|---|
| 主管－指派加班（列表+新增）| `think4u-overtime-manager` / `-create` | `is_manager()` 或 HR |
| 取消 | `think4u-overtime-cancel` | 建立者本人 |
| 員工－我的加班（確認/拒絕）| `think4u-overtime-employee` / `-emp-decision` | 本人 |
| HR－加班核准 | `think4u-overtime-hr` / `-hr-decision` | HR |

**通知**：每次狀態轉換寄 Email（`_safe_send`，SMTP 未設定則靜默略過）。

## 3. 簽核關卡設定 ⚠️ 未完全串接

**程式**：`think4u/approval_workflow_views.py`｜**Model**：`ApprovalWorkflow` + `ApprovalStep`
**URL**：`/think4u/approval-workflow/`（superuser only）

### 畫面
- 3 欄卡片網格（≤1200px 兩欄、≤820px 單欄），**一職位一卡**，卡內含「請假 / 加班」兩區塊
- 每區塊可動態新增/刪除關卡；關卡類型 5 選：直屬主管 / 部門主管 / 指定角色 / 指定員工 / HR
- 頂部 sticky「**全部儲存**」一次存所有卡片（`-save-all`）；也保留單卡儲存（`-save`）
- 沒有任何關卡的項目 → 刪除該 workflow，回到預設流程

### ⚠️ 現況落差
| 類型 | 是否吃這個設定 |
|---|---|
| 補打卡 | ✅ 有（可作為實作範本）|
| 加班申請（OvertimeApplication）| ✅ 有 |
| **請假** | ❌ **沒有**，仍走寫死「主管→HR」|
| **加班指派**（OvertimeAssignment）| ❌ 沒有，走自己的 7 狀態機 |

→ 待辦 C1（Phase 4）：把請假流程改吃 ApprovalWorkflow。

## 5. 補打卡（多關卡簽核範本）

**程式**：`think4u/punch_correction_views.py`｜**Model**：`PunchCorrectionRequest`

```
員工前台提交（target_date, check_in, check_out, reason）
   │  → 依員工職位找 ApprovalWorkflow(request_type='punch_correction')
   │  → current_step_order = 1
   ▼
pending ──每關核准──▶ current_step_order += 1
   │                      │
   │                      └─ 已是最後一關 ──▶ ★自動寫入 AttendanceActivity
   │                                          status = 'applied'（終）
   └──任一關駁回──▶ rejected（終）
```
- `decisions` JSON 累積每關決定：`{order, approver_id, decision, note, at}`
- 畫面：員工「我的補打卡」（`-my`，可取消）／簽核者「待我審核」（`-pending`，`-decide`）

## 7. 給假申請

**程式**：`think4u/leave_grant_views.py`｜**Model**：`LeaveGrantRequest`

```
員工前台「申請給假」（選非預設假別 + 天數 + 證明文件 + 事由）
   ▼
pending ──HR核准（可調整核發天數）──▶ approved
   │                                   └─▶ 自動建立/加值 AvailableLeave
   └──HR駁回（填 hr_note）──▶ rejected
```
**畫面**：HR「給假審核」`/think4u/leave-grant/pending/`（可切換看歷史）
**適用假別**：婚假、產假、喪假(3級)、公傷病假、公假、產檢假、陪產假（共 9 種）

## 8. 月度出勤統計 + 薪資試算（系統最複雜頁）

**URL**：`/think4u/attendance/monthly/`｜**程式**：`monthly_attendance_views.py`

### 8-1. 上半部：出勤矩陣
- 員工 × 當月日期，每格：`P`（出勤）/`P/L`（出勤+請假）/`L`（請假）/`—`(無)/`假`(國定假)/`·`(未到職)
- 色彩：綠=出勤、橘=出勤+請假、灰=請假、藍=無打卡、粉=國定假、淺灰=未到職
- hover 顯示：狀態、上下班時間、工時、遲到/早退分鐘、請假明細
- 點擊 → 當日明細頁（`think4u-attendance-day-detail`）
- 每列右側摘要：應出勤天數（**依該員工到職日計算**）、正常/遲到/早退/缺勤數、總工時/總遲到/總早退

### 8-2. 下半部：薪資試算表（HR 可編輯，自動儲存）
| 欄位群 | 內容 |
|---|---|
| 計薪方式 / 時薪 | 下拉切換 monthly/hourly；時薪制隱藏月薪組成 |
| 全薪 / 工時薪資 | 月薪=組成加總；時薪=工時×時薪；到職當月顯示「在職 X/Y 天 → 應發 Z」|
| 本薪 | 可編輯 |
| 津貼項目（2）| 可摺疊群組（伙食/交通）|
| 加給項目（3）| 可摺疊群組（管理/技術管理/薪資）|
| 其他（8）| 可摺疊群組（加班費/特休未休/三節禮金/代墊/全勤/行政助理費）|
| 健保眷屬 | 唯讀（在員工頁維護）|
| 日薪 | ⌈全薪÷30⌉ |
| **勞保投保薪資** | 級距下拉（0=沿用全薪）|
| 勞保自付 | 計算值 |
| **健保投保薪資** | 級距下拉 |
| 健保自付 | 計算值 |
| 請假明細 | 各假別時數→扣薪 |
| 請假扣薪 | 計算值 |
| 計算式 | 完整公式字串（可對帳）|
| 實領 | 計算值 |

**互動**：任何欄位改動 → debounce 600ms → POST `think4u-salary-update` → 後端重算 → 回傳 JSON 更新該列所有計算欄位
**匯出**：`think4u-salary-export` → Excel（與畫面同一套計算，含計薪方式/時薪/工時/投保薪資欄）

### 8-3. 資料範圍（Scope）
| 角色 | 看得到 |
|---|---|
| HR / 系統管理員 | 全公司（排除 `show_in_personal_reports=False` 的角色成員）|
| 部門主管 | 自部門 + 子部門（遞迴）|
| 一般員工 | 只有自己（**即使自己被標記隱藏也看得到自己**）|

## 9. 稽核紀錄

**程式**：`think4u/audit_log.py`（signals）+ `audit_views.py`｜**URL**：`/think4u/audit-log/`（superuser only）

### 攔截機制
```
pre_save   → 從 DB 撈原值掛在 instance._t4u_audit_original
post_save  → 比對欄位差異：CREATE 寫 [null, new]；UPDATE 寫 [old, new]
post_delete→ 整筆快照寫入 {"__deleted__": {...}}
```
**排除清單**：AuditLog 自己（防遞迴）、Session、ContentType、Notification、Permission、Historical*、admin.LogEntry

### 畫面
- 過濾：使用者 / 動作 / Model / Object ID / 日期區間 / 關鍵字；50 筆/頁
- 詳細頁：完整 changes 表（舊→新對比）+ 同物件其他歷史 30 筆
- 保留期限：`purge_audit_log --years 3`（建議排程每月）

## 11. 健保眷屬明細

**程式**：`think4u/dependent_views.py`（純 HTMX 端點）｜**Model**：`HealthInsuranceDependent`
**位置**：員工工作資訊頁的獨立區塊（HTMX `load` 時載入）

| 端點 | 功能 |
|---|---|
| `think4u-dependent-section` | 載入整個區塊（表格 + 新增列）|
| `-add` / `-delete` / `-toggle` | 新增 / 刪除 / 切換加保狀態 |

每次操作後 `sync_dependent_count()` 更新 `EmployeeSalary.dependents`。

## 12. 員工工作資訊頁（三區塊獨立儲存）

**URL**：`/employee/employee-view-update/<id>/`｜**程式**：`employee/views.py::employee_view_update`

| 區塊 | 內容 | 儲存 |
|---|---|---|
| 工作資訊 | 部門/職位/員工類型/角色/到職日/合約結束日 | `form=work` → 「儲存工作資訊」|
| 💰 薪資 / 計薪方式 | 計薪方式/時薪/投保薪資×2/本薪/津貼×2/加給×3 | `form=salary` → 「儲存薪資」（只寫 EmployeeSalary）|
| 👨‍👩‍👧 健保眷屬 | 眷屬明細 | HTMX 即時（各列自有按鈕）|

> 薪資區塊由共用 partial `think4u/templates/think4u/salary/pay_type_section.html` 渲染，
> 且這些欄位在泛用欄位迴圈（`personal_info_as_p.html`）中**被明確略過**以免重複渲染。
