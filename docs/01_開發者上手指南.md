# 01 開發者上手指南（Think4U HRMS）

> 目標：接手的開發者照本文件，**第一天**就能在本機跑起系統並開始改程式。
> 專案背景與規範另見根目錄 `CLAUDE.md`（開發守則 + 完整 Changelog，必讀）。

## 1. 專案基本資料
| 項目 | 值 |
|---|---|
| Repo | https://github.com/davidkao-coder/horilla-hr （上游 fork 自 Horilla HRMS）|
| 開發分支 | `1.0`（唯一使用中的分支）|
| 技術棧 | Python 3.10 / Django 4.2 / PostgreSQL 16 / HTMX + Bootstrap 5（無前端框架、無 build 流程）|
| 客製核心 | `think4u/` app（所有新功能都放這裡）|
| 介面語言 | 繁體中文 zh-Hant（gettext，po 檔在 `horilla/locale/zh_Hant/`）|

## 2. 本機環境建置（Windows + Docker Desktop）
```bash
git clone https://github.com/davidkao-coder/horilla-hr.git honsi-hrms
cd honsi-hrms
git checkout 1.0
docker compose up -d          # 起 server(8001) + db(host 5433)
docker compose logs -f server # 等到出現 "Listening at: http://0.0.0.0:8000"
```
- 開 http://localhost:8001 → 後台；http://localhost:8001/portal/ → 員工前台。
- 預設管理帳號：`admin`（密碼見密鑰清單；entrypoint 每次啟動會確保 admin 存在）。
- **開發模式整個專案目錄直接掛載進容器**（`docker-compose.override.yaml`），改 Python/template 存檔即生效（Python 改動需 `docker compose restart server`；template 不用）。

### 資料初始化（擇一）
| 方式 | 指令 | 用途 |
|---|---|---|
| 還原正式備份 | `bash scripts/restore.sh <備份目錄>` | 拿到真實資料（備份在 `../backup/`）|
| 種子資料 | `docker compose exec server python manage.py seed_think4u_data` | 乾淨測試環境（4 部門/11 帳號）|

### 常用指令
```bash
docker compose logs -f server                       # 看 log
docker compose restart server                       # 重啟（改 .py 後）
docker compose exec server python manage.py shell   # Django shell
docker compose exec server python manage.py makemigrations think4u
docker compose exec server python manage.py migrate
docker compose exec server python manage.py compilemessages -l zh_Hant  # 改 po 後
```
> ⚠️ **git-bash 下 exec 帶路徑參數時要加 `export MSYS_NO_PATHCONV=1`**，否則 `/app/...` 會被轉成 `C:/Program Files/Git/app/...`。

## 3. Management Commands 一覽（何時用）
| 指令 | 用途 | 何時跑 |
|---|---|---|
| `seed_think4u_data` | 建種子組織/帳號/假別 | 全新環境 |
| `configure_roles [--dump]` | 4 個角色配 Django permissions | 角色權限被弄亂時重置 |
| `precompute_annual_leave --emp <id> [--reset]` | 依到職日預算 20 年特休 | **每位新人入職時** |
| `seed_default_leaves --emp <id>` | 給預設假別配額（特休/事假/病假/生理假）| **每位新人入職時** |
| `import_attendance --folder /app/import_data --year YYYY [--dry-run] [--no-purge]` | 匯入出勤 Excel（**會先清該年再重建**）| 出勤資料更新時 |
| `notify_unpunched [--dry-run]` | 當日未打卡提醒（email+站內）| 排程每日 10:30 |
| `purge_audit_log --years 3 [--dry-run]` | 清 3 年前稽核紀錄 | 排程每月 |
| `sync_annual_leave` / `grant_six_month_leave` / `year_end_leave_settlement` | 特休舊制工具（Model B 後多由 precompute 取代）| 少用，見 CLAUDE.md WP-05 |

## 4. 程式結構速覽
```
honsi-hrms/
├─ think4u/                ← 客製核心（models/views/urls/templates/think4u/...）
│   ├─ payroll_rules.py        台灣勞健保級距 + 計薪公式（金額一律無條件進位）
│   ├─ attendance_rules.py     出勤判定（彈性時段/午休/工時）
│   ├─ attendance_compute.py   出勤彙總（daily_evaluations / worked_minutes_for）
│   ├─ monthly_attendance_views.py  月度出勤統計 + 薪資試算（最複雜的一頁）
│   ├─ portal_views.py         員工前台（GPS 座標在檔頭 COMPANY_GPS_LAT/LNG）
│   ├─ google_auth.py          Google SSO（OAuth code flow）
│   ├─ manager_utils.py        主管判定（直屬主管 ∪ 部門主管）
│   ├─ admin_gate_middleware.py 前後台分離守門
│   └─ management/commands/    上表指令
├─ base/ employee/ attendance/ leave/   ← Horilla 原生（部分已客製，見 docs/02）
├─ horilla/settings.py         設定（env 注入；讀 BASE_DIR/.env）
├─ templates/                  全域 template（index.html=後台外框、login.html）
├─ docs/                       ← 本系列文件
└─ scripts/                    備份/還原/部署腳本
```

## 5. 測試
```bash
docker compose exec server python manage.py test think4u.tests
# 涵蓋：特休計算 15 案例（test_annual_leave）、病假附件驗證（test_sick_leave_validation）
```
改**計薪 / 特休 / 出勤規則**前先跑一次，改完必須全綠。

## 6. 開發守則（重點，完整版見 CLAUDE.md）
1. 新功能一律放 `think4u/`；不直接改 Horilla 原生 template（放 `templates/think4u/`）。
2. **禁止改 Horilla 原生 migration**；新 migration 正常建（repo 預設 gitignore migrations，需要 `git add -f`）。
3. Python 不 hardcode 中文（用 gettext + po）；template 可直接寫中文包 `{% trans %}`。
4. Shell script 一律 **LF** 換行（CRLF 進容器跑不動）。
5. 改完必在 `CLAUDE.md` Changelog 記一筆。
6. **動手前先讀 `docs/02_與上游差異與地雷清單.md`**——會省你很多天。
