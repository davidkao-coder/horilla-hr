## 1. 出勤判定演算法

**程式**：`think4u/attendance_rules.py`（pure functions，無 DB 依賴）

### 1-1. 規則常數
```python
CHECK_IN_FLEX_START  = 09:30   # 彈性上班區間起
CHECK_IN_FLEX_END    = 10:00   # > 10:00 = 遲到
CHECK_OUT_FLEX_START = 18:30   # < 18:30 = 早退
CHECK_OUT_FLEX_END   = 19:00
LUNCH_START/END      = 12:30–13:30（不計工時）
REQUIRED_WORK_MINUTES = 480     # 每日 8 小時
週六日 / 國定假日 不計考勤
```

### 1-2. `evaluate(check_in, check_out, leave_minutes)` 判定順序

```
1. 全天請假（leave_minutes >= 480）           → status = on_leave
2. 無上班也無下班打卡                          → status = absent（缺勤）
3. 只有單邊打卡（缺上班或缺下班）               → status = incomplete（未打卡完整）
4. 兩邊都有 → 計算：
     work_minutes = (out - in) - 午休重疊
     late_minutes  = max(0, in  - 10:00)
     early_minutes = max(0, 18:30 - out)
   4a. 若 work_minutes + leave_minutes >= 480  → status = on_time（正常）
       ★ 遲到/早退分鐘一律歸 0（有請假補足即視為正常）
   4b. 否則依 late/early 有無值：
       late>0 且 early>0 → late_and_early
       late>0           → late
       early>0          → early_leave
       兩者皆 0 但工時不足 → incomplete（含 short_minutes）
```

### 1-3. 計算範例

| # | 上班 | 下班 | 請假 | 工時 | 判定 | 說明 |
|---|---|---|---|---|---|---|
| 1 | 09:45 | 18:50 | 0 | 8h05m | **on_time** | 彈性區間內，工時足 |
| 2 | 10:15 | 19:00 | 0 | 7h45m | **late**（遲 15 分）| 超過 10:00 |
| 3 | 10:15 | 19:30 | 0 | 8h15m | **on_time** | 雖遲到但工時已足 → 歸正常 |
| 4 | 09:30 | 18:00 | 0 | 7h30m | **early_leave**（早退 30 分）| |
| 5 | 09:30 | 14:00 | 4h（下午請假）| 3h30m | **on_time** | 3.5h + 4h = 7.5h < 8h ⚠️ 實際會判 incomplete |
| 6 | — | — | 8h | — | **on_leave** | 全天請假 |
| 7 | 09:30 | — | 0 | — | **incomplete** | 忘打下班卡 |
| 8 | — | — | 0 | — | **absent** | 該出勤未出勤 |

> ⚠️ 範例 5 提醒：請假時數 + 工時必須 **≥ 8h** 才算正常，這是常見誤解。

### 1-4. 請假工時的特殊算法（與出勤工時不同！）

**兩套午休扣除規則，不可混用**：

| 函式 | 用途 | 午休規則 |
|---|---|---|
| `_lunch_deduction()` | **出勤**工時 | 「跨越 13:00 且工時 > 5h」才扣 60 分 |
| `leave_work_minutes()` | **請假**時數 | 直接算與 12:30–13:30 的**重疊分鐘** |

`leave_work_minutes(start, end)` = (end − start) − overlap(12:30–13:30)

| 請假時段 | 計算 | 結果 |
|---|---|---|
| 09:30–18:30 | 9h − 1h | **8h** |
| 09:30–12:30 | 3h − 0 | **3h** |
| 13:30–18:30 | 5h − 0 | **5h** |
| 09:30–14:00 | 4.5h − 1h | **3.5h** |
| 12:00–14:00 | 2h − 1h | **1h** |

另有 `allowed_off_time(start)` = start + 9h（顯示「可下班時間」）。

> 📌 曾發生 bug：誤用 `_lunch_deduction` 算請假時數，導致 09:30–14:00 算成 5h（正確 3.5h）。

## 3. 計薪演算法 ★核心

**程式**：`think4u/payroll_rules.py`（pure）+ `monthly_attendance_views._build_salary()`（組裝）

### 3-1. 全域規則
| 規則 | 值 |
|---|---|
| 計薪基準 | **30 天**（`PAYROLL_BASE_DAYS`），日薪 = 全薪 ÷ 30 |
| 金額取整 | **一律無條件進位到元（`math.ceil`）**，且「先進位再做後續計算」|
| 全薪（gross）| 本薪 + 伙食 + 交通 + 管理加給 + 技術管理加給 + 薪資加給 |

### 3-2. 勞保自付額
```
投保級距 = 第一個 >= 投保薪資的 LABOR_GRADES 值（上限 45,800）
勞保自付 = ⌈級距 × 12.5% × 20%⌉
           （12.5% = 普通事故 11.5% + 就業保險 1%；20% = 受僱者自付比例）
```
| 投保薪資 | 級距 | 自付額 |
|---|---|---|
| 28,590 | 28,590 | ⌈715.0⌉ = **715** |
| 42,000 | 42,000 | ⌈1050.0⌉ = **1,050** |
| 50,000 | 45,800（上限）| ⌈1145.0⌉ = **1,145** |
| 80,000 | 45,800（上限）| **1,145** |

### 3-3. 健保自付額
```
投保級距 = 第一個 >= 投保薪資的 HEALTH_GRADES 值
眷屬數  = min(dependents, 3)   ← 計費上限 3 人
每人保費 = 級距 × 5.17% × 30%
健保自付 = ⌈每人保費 × (1 + 眷屬數)⌉
```
| 投保薪資 | 級距 | 眷屬 | 自付額 |
|---|---|---|---|
| 42,000 | 42,000 | 0 | ⌈651.42⌉ = **652** |
| 50,000 | 50,600 | 0 | ⌈784.81⌉ = **785** |
| 50,000 | 50,600 | 1 | ⌈1569.6⌉ = **1,570** |
| 80,000 | 80,200 | 1 | **2,488** |

### 3-4. 投保薪資的來源（優先序）
```
labor_insured_salary  > 0  → 用它
                      = 0  → fallback 用 gross（全薪）
health_insured_salary 同理
```
> 設計理由：實務上投保薪資由 HR 依級距表指定，**不應與薪資欄位連動**（可能刻意低報或有上限）。

### 3-5. 請假扣薪
```
日薪 = ⌈全薪 ÷ 30⌉                     ← 先進位
各假別扣薪 = ⌈(1 − 給薪比例) × 日薪 × (該假別時數 ÷ 8)⌉   ← 各自進位
總扣薪 = Σ 各假別扣薪                    ← 進位後才加總（保證明細=總額）
```

**給薪比例表（`LEAVE_PAY_RATIO`）**：
| 假別 | 比例 | 扣薪 | 法源 |
|---|---|---|---|
| 事假 | 0.0 | **全扣** | 勞工請假規則 §7 |
| 病假（普通傷病）| 0.5 | **半扣** | 勞工請假規則 §4 |
| 生理假 | 0.5 | **半扣** | 性平法 §14 |
| 特休假 / 公假 / 婚假 / 喪假(3級) / 產假 / 產檢假 / 陪產假 / 公傷病假 / 補休 | 1.0 | 不扣 | |
| 未列出的假別 | 1.0 | 不扣（安全預設）| |

**範例**（全薪 50,000，日薪 ⌈1666.67⌉ = 1,667）：
| 假別 | 時數 | 天數 | 計算 | 扣薪 |
|---|---|---|---|---|
| 事假 | 4h | 0.5 | ⌈1.0 × 1667 × 0.5⌉ = ⌈833.5⌉ | **834** |
| 病假 | 4h | 0.5 | ⌈0.5 × 1667 × 0.5⌉ = ⌈416.75⌉ | **417** |
| 合計 | | | | **1,251** |

### 3-6. 月薪制實領公式
```
實領 = 應發全薪 − 勞保自付 − 健保自付 − 請假扣薪 + 其他加項

其中 應發全薪 = 全薪 × 到職比例（見 §3-8）
     其他加項 = MonthlyPayExtra 8 項加總（不計入投保薪資）
```

**完整範例**（全薪 50,000、無眷屬、事假 4h、其他 0）：
```
全薪            50,000
勞保自付        − 1,145   (級距 45,800)
健保自付        −   785   (級距 50,600)
請假扣薪        −   834   (事假 4h)
其他加項        +     0
─────────────────────────
實領            47,236
```

### 3-7. 時薪制（`pay_type = 'hourly'`）
```
工時薪資 = ⌈當月實際工作時數 × 時薪⌉      ← 請假時數一律不給薪
投保薪資 = 未指定時以工時薪資估算對級距
實領    = 工時薪資 + 其他加項 − 勞保 − 健保
```
**三項決策**（2026-07 拍板）：① 投保薪資用「時薪×工時」估算 ② 加班費手填「其他」欄 ③ **給薪假一律不給薪**

**範例**（時薪 250、當月工時 203.57h、其他 3,000；未指定投保薪資 → 以工時薪資對級距）：
```
工時薪資 = ⌈203.57 × 250⌉ = ⌈50,892.5⌉ = 50,893
勞保（級距 45,800 上限）  − 1,145
健保（級距 53,000）       −   823    ← 50,893 對到的級距是 53,000，非 50,600
其他                      + 3,000
──────────────────────────────
實領                       51,925
```
> 已用實際系統驗算：`compute_hourly_salary(250, 203.57*60, extra_total=3000)`
> → `work_pay=50893, labor=1145, health=823, health_grade=53000, net=51925`

### 3-8. 到職當月比例計薪
**程式**：`monthly_attendance_views._employment(emp, year, month)`

```
到職日 <= 當月 1 日           → 比例 = 1.0（整月）
到職日 >  當月最後一日          → 比例 = 0.0（尚未到職，完全不計薪、不計勞健保）
否則（到職當月）               → 比例 = (當月最後一日 − 到職日 + 1) ÷ 當月天數
                                        ↑ 在職日曆天數（非工作日數）
應發全薪 = ⌈全薪 × 比例⌉
```

**同時影響出勤**：到職前的日子標記 `pre-hire`，**不算應出勤、不算缺勤**；
月度摘要的「應出勤天數」改為該員工當月實際在職的工作日數。

**範例**（Frank，2026-06-08 到職，全薪 50,000）：
| 月份 | 在職天數 | 比例 | 應發 | 勞健保 | 實領 |
|---|---|---|---|---|---|
| 2026/05 | 0/31 | 0.0 | **0** | 0 / 0 | **0** |
| 2026/06 | 23/30 | 0.7667 | ⌈38,333.3⌉ = **38,334** | 1,145 / 785 | **36,404** |
| 2026/07 | 31/31 | 1.0 | **50,000** | 1,145 / 785 | **48,070** |

> ⚠️ 勞健保在到職當月仍**整月投保**（保守做法，多繳不少繳）；離職當月比例尚未實作。

### 3-9. 級距表維護（每年必做）
```python
# think4u/payroll_rules.py
LABOR_RATE = 0.125            # 勞保費率（普通事故+就保）
LABOR_EMPLOYEE_SHARE = 0.20   # 受僱者自付比例
HEALTH_RATE = 0.0517          # 健保費率
HEALTH_EMPLOYEE_SHARE = 0.30
LABOR_GRADES = [28590, ..., 45800]        # 11 級（上限 45,800）
HEALTH_GRADES = [28590, ..., 219500]      # 48 級
```
> 每年勞健保調整時**只改這些常數**，計算、UI 下拉、Excel 匯出全部自動跟著變。

## 4. 特休演算法（Model B：週年制獲假 + 曆年使用）

**程式**：`think4u/services/annual_leave_calculator.py` + `precompute_annual_leave` 指令

### 4-1. 年資級距（勞基法 §38）
| 年資 | 天數 |
|---|---|
| 滿 6 個月 | 3 |
| 滿 1 年 | 7 |
| 滿 2 年 | 10 |
| 滿 3–4 年 | 14 |
| 滿 5–9 年 | 15 |
| 滿 10 年起 | 16，每年 +1，上限 30 |

### 4-2. Model B 的兩段式拆分
每到週年日獲得該年資的天數，但因公司採**曆年使用**，故拆兩段：

```
週年日獲假 tier_days 天
  ├─ 第 1 段（當年剩餘）：天數 = floor_to_half(tier × 當年剩餘月數 ÷ 12)
  │                        可用區間 = 週年日 ~ 當年 12/31
  └─ 第 2 段（隔年完整）：天數 = tier − 第1段
                           可用區間 = 隔年 1/1 ~ 隔年 12/31
```
- `floor_to_half`：0.5 天精度**向下取**（如 4.7 → 4.5）

**範例**（到職 2026-06-08）：
| 年資 | 週年日 | tier | 第1段（當年）| 第2段（隔年）|
|---|---|---|---|---|
| 滿半年 | 2026-12-08 | 3 | 0 天（12/8~12/31）| 3 天（2027 全年）|
| 滿1年 | 2027-06-08 | 7 | 3.5 天（6/8~12/31）| 3.5 天（2028）|
| 滿2年 | 2028-06-08 | 10 | 5.5 天 | 4.5 天 |
| 滿3年 | 2029-06-08 | 14 | 7.5 天 | 6.5 天 |

### 4-3. 遞延規則
**僅前一年未休完可遞延一年**（勞基法 §38-4 約定遞延）：
`grant_type = 'carryforward'`，區間為隔年 1/1–12/31。

### 4-4. 執行方式
```bash
python manage.py precompute_annual_leave --emp <id> [--reset] [--years 20]
```
- 一次算未來 20 年全部 `LeaveAllocation`（**不需 cron**）
- 同步寫 `AvailableLeave.available_days` = 所有「今天落在 start~end 區間」的配額加總
- **新人入職必跑**

## 6. 簽核流程規則

### 6-1. 現行（寫死）
| 類型 | 流程 |
|---|---|
| 請假 | 員工申請 → **主管**核准（第一層）→ **HR**核准（第二層）|
| 加班指派 | 主管指派 → **員工**確認 → **HR**核准 |
| 加班申請 | 員工申請 → 走 ApprovalWorkflow（若無設定則預設主管→HR）|
| 補打卡 | 員工申請 → **走 ApprovalWorkflow 多關卡** → 最後一關核准後自動寫入出勤 |

### 6-2. 「主管」的判定
```
is_manager(user) = Horilla 直屬主管（EmployeeWorkInformation.reporting_manager_id）
                 ∪ Think4U 部門主管（Department.manager，含子部門遞迴）

managed_employees(user) = 直屬下屬 ∪ 所管部門(含子部門)成員 ∪ 自己
```
> ⚠️ 一律使用 `manager_utils` 的這兩個 helper，**不要用 Horilla 的 `is_reportingmanager`**。

## 8. 已知與法規的偏差（有意識的決策）

| 項目 | 法規要求 | 系統現況 | 決策 |
|---|---|---|---|
| 產假給薪 | 勞基法 §50：年資 <6 月**半薪**、≥6 月全薪 | 一律全薪 | 暫緩（對員工有利、無違法風險）|
| 勞保到職當月 | 可按日計保 | 整月投保 | 簡化（多繳）|
| 離職當月比例 | 應按日計 | 未實作 | 無案例，遇到再做 |
| 補休轉換 | 加班可換補休 | 未自動轉換，需人工 | 待辦 C3 |

> 完整決策紀錄（含待補拍板人）見 `docs/03_業務規則決策紀錄.md`。
