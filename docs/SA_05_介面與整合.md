## 2. HTMX 端點設計

系統大量使用 HTMX「回傳 HTML 片段」而非 JSON API。判斷方式：

| 情境 | 回傳 | 例子 |
|---|---|---|
| 局部區塊更新 | **HTML 片段** | 健保眷屬區塊（`dependent-section` 回整個 div）|
| 表單提交後重繪 | HTML 片段 + `hx-swap="outerHTML"` | 眷屬新增/刪除/切換 |
| 純資料計算 | **JSON** | `salary/update`（回傳全部計算欄位）、`api/position-default-role` |

**慣例**：
- HTMX 端點的 view 通常用 `@login_required` + 手動權限檢查（非 CBV）
- 回傳片段的 template 放在對應模組的 `templates/think4u/<模組>/` 下
- 用 `hx-target` + `hx-swap="outerHTML"` 讓片段能自我替換

**範例**（眷屬區塊）：
```html
<div hx-get="{% url 'think4u-dependent-section' employee.id %}" hx-trigger="load"></div>
<!-- 內部按鈕 -->
<button hx-post="{% url 'think4u-dependent-toggle' d.id %}"
        hx-target="#dependentsSection" hx-swap="outerHTML">加保中</button>
```

## 3. Google SSO 整合

**程式**：`think4u/google_auth.py`｜**流程**：OAuth 2.0 Authorization Code Flow（自寫，不用 allauth）

```
[1] 使用者點「使用 Google 登入」
      GET /think4u/google/login/?dest=portal|admin
      → 產生隨機 state 存 session（防 CSRF）
      → dest 存 session
      → 302 到 accounts.google.com/o/oauth2/v2/auth
         params: client_id, redirect_uri, response_type=code,
                 scope="openid email profile", state, prompt=select_account,
                 hd=think4u-tech.com（單一網域時提示預選）
[2] 使用者在 Google 選帳號 → Google 302 回
      GET /google/callback?code=...&state=...
[3] 後端驗證：
      state 相符？（pop session，防重放）
      → POST oauth2.googleapis.com/token（code + client_id + secret + redirect_uri）
      → 取 id_token（JWT），解 payload（TLS 直連 Google，故免驗簽）
      → 驗 iss ∈ {accounts.google.com, https://accounts.google.com}
        驗 aud == CLIENT_ID
        驗 email_verified == true
      → 驗 email 網域 ∈ GOOGLE_OAUTH_ALLOWED_DOMAINS（預設 think4u-tech.com）
      → 以 email 找既有 User（username iexact，備援 email iexact）
        ★ 找不到 → 拒絕（不自動開帳號）
      → 檢查 user.is_active、employee 存在且 is_active
      → login() → 依 dest + 角色導向（同 login_user 規則）
```

**設定**（`.env`）：
```
GOOGLE_OAUTH_CLIENT_ID=371052581500-...apps.googleusercontent.com
GOOGLE_OAUTH_CLIENT_SECRET=...
GOOGLE_OAUTH_ALLOWED_DOMAINS=think4u-tech.com   # 選填，預設即此
```
未設 CLIENT_ID → 登入頁自動不顯示按鈕。

**Google Console 需登記的 Redirect URI**（根路徑、**無結尾斜線**）：
```
https://hrms.think4u-tech.com/google/callback      ← 已登記
http://localhost:8001/google/callback             ← 本機測試需自行加
```
> ⚠️ `_redirect_uri()` 對非 localhost 主機**強制改寫為 https**（DEBUG 下 Django 看不到
> `X-Forwarded-Proto` 會誤判 http，造成 `redirect_uri_mismatch`）。

## 4. Excel 匯入格式（出勤）

**指令**：`import_attendance --folder /app/import_data --year YYYY [--dry-run] [--no-purge]`

### 4-1. 檔名規則
```
(宏思)出勤_請假_加班_員工：<EnglishName>(<中文名>).xlsx
                        ^^^^^^^^^^^^^ 用 regex 「員工：([A-Za-z]+)」抓取
```
→ EnglishName 必須與 `Employee.employee_first_name` 相符（不分大小寫）。

### 4-2. Sheet 與欄位
必須有 sheet **`01_出勤明細表`**，欄位（index 從 0）：
| Index | 欄位 | 用途 |
|---|---|---|
| 0 | 年度 | |
| 1 | 月份 | |
| **2** | **出勤日期** | `COL_DATE`，datetime |
| 3 | 星期幾 | |
| **4** | **上班時間** | `COL_IN`，time 或 "HH:MM" |
| **5** | **下班時間** | `COL_OUT` |
| 6 | 出勤時數 | （不採用，系統自算）|
| 7 | 出勤異常 | `COL_ABNORMAL` |
| 8 | 出勤異常原因 | |
| **9** | **核准假別** | `COL_LEAVE_TYPE_APPROVED`（fallback）|
| 10 | 核准請假時數 | |
| **11** | **核准加班時數** | `COL_OT_HOURS` |
| 12 | 補休時數 | |
| **13** | **請假申請（假別）** | `COL_LEAVE_APPLICATION`（優先；"請選擇" 視為空）|
| 14 | 起/迄時間 | `COL_LEAVE_PERIOD`，支援 "17:00~19:00" |
| 15 | 請假時數 | `COL_LEAVE_HOURS`（0 或空 → 預設 8h）|
| 16 | 請假原因 | |
| 17–19 | 代理人/注意事項/證明文件 | |

其他 sheet：`02_請假總覽`、`03_特休資訊(採曆年制)`（含**員工到職日**）、`04_請假貼圖`

### 4-3. 假別對照（`LEAVE_TYPE_MAP`）
事假 / 特休 / 病假 / 公假 / 婚假 / 補休 / 生理假 / 產假 / 陪產假 / 產檢假 → 對應 `LeaveType.name`

### 4-4. ⚠️ 破壞性行為
```
--year 2026 執行時：
  1. 先 DELETE 該年度【全公司】的 AttendanceActivity / LeaveRequest / OvertimeApplication
  2. 再依 Excel 重建
→ 系統內未回寫進 Excel 的手動修改會消失
→ 用 --no-purge 可跳過清除（但可能產生重複）
→ 建議先 --dry-run 預覽
```
匯入後自動同步 `WorkRecord`。

## 7. Email 通知

**機制**：`_safe_send(subject, body, recipients)` — 包 Django `send_mail`，**SMTP 未設定時靜默略過**（不拋錯）。

| 觸發 | 收件者 |
|---|---|
| 加班指派建立 | 員工 |
| 員工確認加班 | HR 群組 |
| 員工拒絕加班 | 指派主管 |
| HR 核准/駁回加班 | 主管 + 員工 |
| 每日未打卡提醒 | 未打卡員工 |

**郵件自動化模組**（`horilla_automations`，Horilla 原生已中文化）：
可設定「資料模型 × 觸發時機（建立/更新/刪除） → 收件人（依模型欄位路徑）+ 郵件範本」。
⚠️ 必須先選「資料模型」，收件人下拉才會依該模型動態載入。
