# SA-02 資料模型（Think4U HRMS）

> 13 張 Think4U 自製表 + 與 Horilla 原生表的關係。所有表名前綴 `think4u_`。

## 2. 各表詳細 Schema

### 2-1. EmployeeSalary（員工薪資設定）— 1:1 Employee
計薪的**單一真實來源**。所有薪資計算都從這裡取值。

| 欄位 | 型別 | 說明 |
|---|---|---|
| employee | OneToOne→Employee | |
| **pay_type** | CharField | `monthly`（月薪制，預設）/ `hourly`（時薪制）|
| **hourly_rate** | PositiveInteger | 時薪（時薪制用）|
| base_salary | PositiveInteger | 本薪（預設 50000）|
| meal_allowance | PositiveInteger | 伙食津貼 |
| transport_allowance | PositiveInteger | 交通津貼 |
| management_allowance | PositiveInteger | 管理加給 |
| tech_management_allowance | PositiveInteger | 技術管理加給 |
| salary_addition | PositiveInteger | 薪資加給 |
| dependents | PositiveSmallInteger | 健保眷屬**人數**（由 HealthInsuranceDependent 明細同步）|
| **labor_insured_salary** | PositiveInteger | 勞保投保薪資（0=沿用全薪估算）|
| **health_insured_salary** | PositiveInteger | 健保投保薪資（0=沿用全薪估算）|
| monthly_salary | PositiveInteger | ⚠️ 舊欄位，已被組成欄位取代，保留相容 |

- **property `gross`** = base + 兩津貼 + 三加給（= 全薪）
- 常數 `SALARY_COMPONENT_FIELDS` 定義 UI 顯示的 6 個組成欄位（key, 標籤, 群組）

### 2-2. MonthlyPayExtra（每月變動加項）— unique(employee, year, month)
| 欄位 | 說明 |
|---|---|
| overtime_pay | 加班費 |
| unused_annual_leave | 特休未休 |
| birthday_gift / dragonboat_gift / midautumn_gift | 生日/端午/中秋禮金 |
| expense_reimbursement | 給付代墊公司費用 |
| perfect_attendance_bonus | 全勤獎勵金 |
| admin_assistant_fee | 行政助理費 |

- **property `total`** = 8 項加總；常數 `EXTRA_PAY_FIELDS`
- ⚠️ 這些**不計入勞健保投保薪資**，只在最後加回實領

### 2-3. HealthInsuranceDependent（健保眷屬明細）
| 欄位 | 說明 |
|---|---|
| name / relationship / national_id / birth_date / enroll_date | 眷屬基本資料 |
| is_enrolled | 是否加保中（計費只算加保中者）|

- helper `sync_dependent_count(employee)`：重算並寫回 `EmployeeSalary.dependents`
- 健保計費眷屬**上限 3 人**（在 `payroll_rules` 限制，非此表）

### 2-4. LeaveAllocation（特休配額，Model B 核心）
每個週年日產生**兩筆**：當年剩餘段 + 隔年完整段。

| 欄位 | 說明 |
|---|---|
| employee / leave_type | |
| service_years | 服務年資（0=滿半年、1=滿1年…）|
| anniversary_date | 週年日（獲假日）|
| tier_days | 該年資級距應得天數（如滿1年=7）|
| **grant_type** | `anniversary`（週年獲假）/ `carryforward`（遞延）|
| days_granted | 本段實際給假天數 |
| days_used | 已使用 |
| start_date / end_date | 可請休區間 |

- `precompute_annual_leave` 一次算 20 年，同步寫 `AvailableLeave.available_days`
- 詳細演算法見 SA-04 §4

### 2-5. AnnualLeaveRecord（特休年度記錄，舊制）
`year / allocated_days / used_days / carried_over / carry_over_expire / source / note`
→ 早期 WP-05 產物，Model B 上線後主要由 LeaveAllocation 取代，**新功能不要用這張表**。

### 2-6. LeaveGrantRequest（給假申請）
非預設假別（婚/產/喪/公傷/公假/產檢/陪產）必須申請。

| 欄位 | 說明 |
|---|---|
| employee / leave_type / requested_days / reason | 申請內容 |
| proof_document | FileField 證明文件 |
| status | `pending` / `approved` / `rejected` |
| granted_days | HR 實際核發（可與申請不同）|
| hr_note / decided_by / decided_at | 審核結果 |

核准時自動建立或加值 `AvailableLeave`。

### 2-7. OvertimeAssignment（主管指派加班）— 7 狀態機
| 狀態 | 意義 |
|---|---|
| `pending_employee` | 待員工確認（初始）|
| `employee_confirmed` | 員工已確認 |
| `employee_rejected` | 員工拒絕（需填理由）|
| `pending_hr` | 待 HR 核准 |
| `hr_approved` | HR 已核准（終態）|
| `hr_rejected` | HR 駁回（終態）|
| `cancelled` | 已取消（僅 pending_employee 可取消）|

其他欄位：`overtime_date / start_time / end_time / reason / employee_note / hr_note / employee_confirmed_at / hr_approved_at`

### 2-8. OvertimeApplication（員工主動申請加班）
與上表並存但走 **ApprovalWorkflow 多關卡**：
`employee / overtime_date / start_time / end_time / reason / status / workflow→ApprovalWorkflow / current_step_order / decisions(JSON)`

### 2-9. PunchCorrectionRequest（補打卡申請）
`employee / target_date / requested_check_in / requested_check_out / reason / status / workflow / current_step_order / decisions(JSON)`

- **這是唯一真正在跑 ApprovalWorkflow 的模組**（可作為 Phase 4 的實作範本）
- `decisions` JSON 結構：每關的 `{order, approver_id, decision, note, at}`
- 最後一關核准 → 自動寫入 `AttendanceActivity`，status 轉 `applied`

### 2-10. ApprovalWorkflow / ApprovalStep（簽核關卡設定）
| ApprovalWorkflow | |
|---|---|
| job_position | FK→JobPosition（每個職位一組流程）|
| request_type | `leave` / `overtime` / `punch_correction` |
| is_active / note | |

| ApprovalStep | |
|---|---|
| workflow / order | 關卡順序 |
| **approver_type** | `direct_manager`（直屬主管）/ `department_head`（部門主管）/ `role`（指定角色）/ `employee`（指定員工）/ `hr` |
| approver_role | FK→Group（type=role 時用）|
| approver_employee | FK→Employee（type=employee 時用）|

> ⚠️ **現況**：設定頁完整可用，但**只有補打卡真正吃這個設定**；請假/加班仍走寫死的「主管→HR」。

### 2-11. AdminAccessGroup（前後台/權限旗標）— 1:1 Group
`group / can_access_admin / force_admin_only / show_in_personal_reports / acts_as_superuser`
→ 詳見 SA-00 §3-2

### 2-12. AuditLog（稽核紀錄）
| 欄位 | 說明 |
|---|---|
| timestamp | 索引 |
| user / user_repr | 操作者（user_repr 保留字串，即使 User 被刪也看得到）|
| action | `CREATE` / `UPDATE` / `DELETE` |
| model_label / object_id | 目標物件（複合索引），**不用 FK**（要能記錄已刪除物件）|
| object_repr | 物件字串表示 |
| changes | JSON：`{欄位: [舊值, 新值]}`；DELETE 時為 `{"__deleted__": {全欄位快照}}` |
| request_path / request_method / ip_address | 來源 |

- 3 個索引：`timestamp`、`(model_label, object_id)`、`user`
- 排除清單（防遞迴/雜訊）：AuditLog 自己、Session、ContentType、Notification、Permission、Historical*、admin.LogEntry

## 3. 與 Horilla 原生表的關係

### 3-1. 大量使用（不可動）
| 原生表 | 用途 | Think4U 的擴充 |
|---|---|---|
| `Employee` | 員工主檔 | 所有自製表都 FK 到它 |
| `EmployeeWorkInformation` | 工作資訊 | 表單大改（薪資組成 mixin、role 單選）；`date_joining` 是計薪/特休關鍵 |
| `Department` | 部門 | **加了 `parent_department_id`（部門樹）+ `manager`（部門主管）** |
| `JobPosition` | 職位 | **加了 `default_role`（FK→Group）** |
| `LeaveType` / `AvailableLeave` / `LeaveRequest` | 請假體系 | LeaveType 加 `half_paid` 選項；AvailableLeave 由特休演算法寫入 |
| `AttendanceActivity` | 打卡明細 | **加了 4 欄：`attendance_type` / `field_reason` / `client_ip` / `verification_code_used`** |
| `Holidays` / `CompanyLeaves` | 假日設定 | 出勤判定會排除 |
| `auth_user` / `Group` | 認證 | Horilla 用 `add_to_class` 加了 `is_new_employee`（⚠️ 見 docs/02 M3）|

### 3-2. 已棄用（表存在但不寫入）
| 原生表 | 為何棄用 |
|---|---|
| `Attendance` | 設計與台灣彈性工時不符，改為即時計算 |
| `AttendanceLateComeEarlyOut` | 同上，改由 `evaluate()` 判定 |
| `payroll_*` | 計薪自製（`payroll_rules.py`）|

> ⚠️ 看到原生頁面顯示「出勤資料為空」是正常的——它們讀的是棄用表。

### 3-3. 保留但不使用（僅為 migration 依賴）
`asset`（資產，有 autocomplete 客製但無 sidebar 入口）、`horilla_documents`、`dynamic_fields`、`recruitment`（model 層）

## 5. 資料完整性注意事項

| 注意點 | 說明 |
|---|---|
| `EmployeeSalary.dependents` 是**衍生值** | 改 HealthInsuranceDependent 後要呼叫 `sync_dependent_count()` |
| `AvailableLeave.available_days` 是**衍生值** | 由 `precompute_annual_leave` 從 LeaveAllocation 算出 |
| Excel 匯入是**破壞性的** | `import_attendance` 會先刪該年度全公司的出勤/請假/加班再重建 |
| 新人必跑兩個指令 | `precompute_annual_leave` + `seed_default_leaves`，否則無假可請 |
| migrations 預設被 gitignore | 新增 migration 要 `git add -f` |
